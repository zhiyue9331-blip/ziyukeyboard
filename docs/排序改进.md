# 字语输入法排序改进

下面四项已经进到 `fix/pinyin-order-0.4.14`。改词库或 Rime 方案时，把 `RimeEngine.DATA_VERSION` 加一，否则已安装的共享数据不会重拷。当前是 7。

- 模糊音同一音节只改一处。`can` 可以到 `chan` 或 `cang`，不能到 `chang`。Java 的 `fuzzyVariants` 和 `ziyu_pinyin_fuzzy.schema.yaml` 用同一条边界。
- 学习加分记在「当时输入的拼音 + 词」上。选一次加 2 分，最多 6 分。没有这条拼音的记录时，名次不动。全局次数只在分数相同时比较。
- 小词库不再整体加 1,000,000。短输入用大词库权重。「你」的手写频率是 990，低于「那」的 1060。因此 `zg` 首位改成权重更高的「这个」，「中国」仍在「中国人」前；`zh` 首位是「中」；`shishi` 首位是「实施」。
- 简表补了「不知道」（`bu zhi dao`，32000）。「野餐」仍是 `ye can`，1720。抽查过的什么、怎么、我们、这个、谢谢、再见、好吃、不好意思、怎么样都已经在表里。

## 已经落地的行为

这些不要再当成待办，改动时要保持住：

- `嗯`、`唔` 没有单字母读音 `n`。`n` 首位是「你」，`en` 首位是「恩」，`ng` 首位仍是「嗯」。
- 单字母未完成音节（`n`、`l`、`sh`）会把能接下去的单字提前。完整音节 `a` 仍是「啊」，不把「爱」抬上来。
- `野餐` 以 `ye can`、权重 1720 收录。模糊音打开时 `yecan` 首位是「野餐」，不是「也常」。
- 删除键点一下删一个；按住约 350 毫秒后每 50 毫秒再删一个，松手或滑出按键即停。

## 1. 模糊音不要在同一音节上叠两层

### 现在

模糊音默认开启。两套规则同时生效：

- Java：`PinyinEngine.fuzzyCanonical` 把 `zh/ch/sh` 收成 `z/c/s`，再把 `ang/eng/ing` 收成 `an/en/in`。查询至少两个字母才走这套；单字母不走。
- Rime：`ziyu_pinyin_fuzzy.schema.yaml` 用一串 `derive`。`c` 可变成 `ch`，`an` 可变成 `ang`。规则按顺序叠在已派生的拼写上，所以音节 `can` 能变成 `chang`。

`也常` 的编码是 `ye chang`，权重 158。在补上「野餐」之前，`yecan` 没有精确词，模糊命中的「也常」占住首位。

### 问题

缺词时，两层模糊会把另一个词变成整段精确码。用户看到的是一个不相关的词，而不是「没有这个词，用单字组出来」。

### 改法

精确拼写始终排在模糊拼写前面。同一音节只允许改一处：声母 `z/zh`、`c/ch`、`s/sh`，或韵尾 `an/ang`、`en/eng`、`in/ing`，不要让 `can` 一步走到 `chang`。`n/l` 继续只对两个字母及以上生效，单字母 `l` 不混入 `n`。

Java 和 Rime 要同一套边界。只改 `fuzzyCanonical` 时，画面仍先采用 Rime 的 24 个候选。

### 验收

- 模糊音开：`yecan` 首位「野餐」；「也常」可以出现，但不能在「野餐」前面。
- 模糊音开：`can` 可以出「参」「餐」，不能靠叠层模糊把「常」放在它们前面。
- 模糊音关：`yecan` 仍是「野餐」，`chang` 仍是「长」。
- 单字母 `l` 前三名没有「嗯」「那个」。`sh` 首位「是」，`ng` 首位「嗯」。

## 2. 学习加分绑在「这段拼音」上

### 现在

`UserLexiconStore.learnedScore` 是候选原分加上 `该字出现次数 × 250`。次数只按汉字记，不按当时的拼音记。`refreshCandidates` 先做这次重排，再做精确单字、简拼和未完成音节的提前。

Rime 一次只回 24 条，分数是 `100000` 减去序号，相邻两条只差 1 分。选错过一次，这个字只要还在这 24 条里，就会被加到最前。后面的 `prefer*` 只在特定查询上把结果拉回来，盖不住所有情况。

合并时如果 Rime 和 Java 都有同一个词，保留的是 Rime 的分数，不是 Java 的两百万级精确加分。所以大词库里的高权重，到了画面上经常只剩这一串相差 1 分的名次。

### 问题

加分跟输入脱离。在 `n` 上选过的字，会出现在别的、碰巧还包含这个字的候选里，并把原有词频差抹平。

### 改法

学习分只加给「当前拼音曾经提交过这个词」。加分要小于正常词之间的词频差，不能大于整页 Rime 名次的总跨度（现在大约 23 分）那么多倍。没有这条拼音的学习记录时，顺序保持引擎原来的名次。

全局字频可以留下，但只能作为同分时的次序，不能单独把后排候选翻到第一。

### 验收

- 在 `n` 上提交一次「你」后，`n` 仍是「你」，`l` 仍是「了」，`en` 仍是「恩」。
- 把一个后排词提交一次，它最多前移几位，不能越过权重明显更高、拼写也精确的词。
- 清空本地学习后，顺序回到没有学习记录时的结果。
- `zg` 仍是「中国」在「中国人」前，`de` 仍是「的」。

## 3. 短输入用大词库词频

### 现在

`PinyinEngine` 先加载 `pinyin_dictionary.tsv`，每条频率加 1,000,000，再加载 `pinyin_rime.tsv` 且不加分。未完成音节上的单字再加 1,600,000。这两项对同一类候选是一样的，于是谁排第一取决于小词库里手写的几十个数字。

小词库里「那」曾经是 1060，「你」是 990。大词库里「你」是 973526，「那」是 269381。加分之后小词库的「那」仍高于大词库的「你」。后来把小词库的「你」改成 1400，`n` 才稳定成「你」。这是在补一个手写数字，不是词频本身。

### 问题

短输入的首位跟真实词频脱节。每发现一个类似「那」压过「你」的例子，就要再改一次小表。

### 改法

查询能在大词库里找到候选时，排序用大词库的原始权重。小词库继续负责大词库还没加载完时的兜底，以及少量必须手调的例子，但不要再用固定的 1,000,000 把整张小表抬到大词库上面。

未完成音节把单字提前的规则保留。比较的是同一规则下的大词库权重。

### 验收

- `n` 首位「你」，`l` 首位「了」，`f` 首位不是「方便」。
- 把小词库里「你」的手写频率改回低于「那」，`n` 的首位仍然是「你」。
- `a` 首位「啊」，`sh` 首位「是」，`de` 首位「的」。

## 4. 按使用频率补常用词

### 现在

`pinyin_simp.dict.yaml` 和由它生成的 `pinyin_rime.tsv` 来自 Android 开源拼音词库的简表。两处要一起改。`tools/generate_dictionaries.ps1` 会从外部词库重写 `pinyin_rime.tsv`；用仍含旧条目的上游文件重跑，会把本地补上的词冲掉。

「野餐」原来不在表里。`野`（`ye`，4734）和 `餐`（`can`，1272）都有，但没有这个词，整段输入就被模糊规则配到了别的词上。同类空缺还会出现。

### 改法

先列一份日常会整段输入、而简表里没有的词，按现有权重尺度补进两份表。附近的参照是「午餐」1036、「早餐」1607、「晚饭」2312。新词要高于误命中的低权重组合（「也常」只有 158），不要高到压过更常见的精确词。

补词后跑一次「输入串 → 首位」检查，至少覆盖这次已经遇到的 `yecan`、`n`、`en`、`ng`、`l`。

### 验收

- `yecan` 模糊开、关都是「野餐」。
- 新词的编码是它的实际拼音，不借用单字母或模糊后的短码。
- `ng` 仍是「嗯」在「那个」前，「那个」在「那个人」前。

## 改动时一起看的测试

`PinyinEngineTest` 和 `CandidateMergeTest` 已经钉住这些结果：`yecan`→野餐，`n`→你，`ng`→嗯，`sh`→是，`zg`→中国，模糊 `l` 的前三名没有「嗯」。改第 1 到第 3 项时先跑这两类测试，再在 MuMu 上用空格提交首位核对。
